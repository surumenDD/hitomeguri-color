# 人物の重ね（試作）の設計

ADR-0009 の試作の、見た目・操作・式・受け入れの基準。メイン（Claude）が持つ視覚の設計で、実装はこの文書に合わせる。採用は利用者が試作を見て決める。それまで main に合流させない。

## 考え方

- 背景は今までどおり、島と台本で色がめぐる。人物は島に分けず、**その時刻の場面の光に照らされた姿**として描く。
- 人物の素材は、場面と関係のない白い光の下で描かれている。そのまま重ねると、台本の始まり（夕方）から場面になじまずに浮く。だから始まりの時刻から、夕焼けの光を受けた姿にする。
- 夜には背景と一緒に暗くなり、空の光の色を受ける。ただし背景ほどは沈めず、顔の線が読める明るさを残す。
- 台本の始まりと終わりで人物は同じ姿になる（ループの継ぎ目が出ない）。「元の絵と1画素も違わない」約束（ADR-0004）は背景だけに当てる。人物の素材は場面の一部ではないため。

## なじませ方（式）

2026-10-27 に改める（v2）。初めの式は「始まりで素材のまま、そこからの変化だけを足す」形だった。利用者の指摘「女の子の初期の色が背景になじまない。初期はなじんでいない基礎素材のままなので、最初からなじむように」を受け、どの時刻でも場面の光に照らす形にした。メインが試作の素材（海辺、お祭り）で強さを試して決めた。

コマごとに、台本から次を求める（CPU で1回）。

- **光の基準色** `S(t)`: 帯の上段の色（上空。面積が最大の「空」の島）と、下段の色（地平。最も暖かい「空」か「水」の島）の、OKLab での平均。上空だけでは、夕方の上空がすでに藍色なので夜の変化が小さく、人物が浮いた（v1 で確かめた）。
- **露出** `E(t) = clamp(S_L(t) / 0.7, 0.3, 1.15)`。
- **光の色** `C(t)`: OKLab `(0.85, 1.3 × S_a(t), 1.3 × S_b(t))` を線形の sRGB に直し（負の値は 0.0001 にする）、最も大きい成分が 1 になるよう割る。白い光は `(1, 1, 1)`。
- 「空」の島が無い絵では、`E = 1`、`C = (1, 1, 1)`（人物は素材のまま）。

人物の各画素（線形の sRGB）に、目盛り「光のなじみ」`f`（0〜1、標準 0.8）を使って次を当てる（シェーダーで）。

```
fg' = fg × (1 + f × (E(t) × C(t) − 1))     … 成分ごとの掛け算
fg' = clamp(fg', 0, 1)
```

- `f = 0` では、どの時刻でも人物は素材のまま。`f = 1` で場面の光をそのまま受ける。
- 台本の始まりと終わりは同じ `S` なので、人物も同じ姿になる。
- 強さの決め方: 光の色の係数 1.3 は、1.0 と 1.5 と 2.5 を試して決めた。2.5 ではお祭りの始まりで女の子が赤く染まり、昼に黄ばんだ。1.5 でもお祭りの赤みが少し強い。1.0 では海辺の夕焼けの橙がやや弱い。
- 見え方（試作の素材、f = 0.8）: 夕方の始まりは、海辺では夕焼けの橙を、お祭りでは提灯の路地に合う暖かい桃色を帯びる。深夜は暗くなり、夜の光の色を受ける。昼は白っぽい光で、黄ばまない。
- v1 の式（L の比、彩度の係数、0.5 × f のずらし、0.35 × L の下限）は使わない。

色域の外に出たら、今と同じ `gamutMap`（L と色相を保ち、彩度を下げる）で戻す。合成は線形の光で行う: `out = bg × (1 − α) + fg' × α`（α は人物のアルファ、ストレートの値）。

島を選んだときと分割中の沈め（L × 0.6、C × 0.25）は、人物にも同じように当てる。人物は島ではないので、強調する側に来ることはない。プレビューだけで、書き出しには当てない。

## 置き方

- **大きさ**: 人物の高さを、絵の高さに対する割合で持つ（20〜120%、標準 70%）。幅は縦横比を保つ。
- **位置**: 人物の下端の中心を、絵の座標（左上 0,0、右下 1,1）で持つ。標準は `x = 0.68`、`y = 1.0`（絵の下端にそろえ、右寄り3分の2の線の近く）。絵からはみ出してよい（はみ出た分は描かない）。
- マウスやタッチでは、人物をドラッグして動かす。
- キーボードでは、人物の外接矩形に重ねた、見えない `button` で動かす。
  - `aria-label` は「人物の位置。矢印キーで動かします」。
  - 矢印キーで 1%、Shift と一緒で 10% 動く。
  - 焦点が来たら、外接矩形に白い 1px の点線を出す（焦点の輪と同じ白）。
- 人物の画像は長い辺を 2048px までに縮めてから使う。
- **位置の範囲**（2026-10-27 追記、adviser の質問への回答。分ける前の絵の構図に近い配置: お祭りは x 0.5・y 1.26・大きさ 105%、海辺は x 0.76・y 1.6・大きさ 120%）: 下端の中心の x は 0〜1、y は 0.2〜（1 ＋ 大きさ × 0.5）。足元から人物の高さの半分までは、絵の下へはみ出してよい。範囲に上下限を設けないと、ドラッグで人物を絵の外へ放り出して見失うため。
- **背景を替えたとき**（同上）: 人物の画像、大きさ、位置、光のなじみは保つ。同じ人物をいろいろな背景に置くことが、この機能の狙いのため。
- **空の元の明るさが 0 のとき**（同上）: 比だけ `k = 1` にし、色のずらしは式どおりに求める。

## パネル

「色の島」の節の下に、節「人物」を足す。見出しの書き方は「色の島」と同じ。

- **人物が無いとき**:
  - 説明（14/20px、`#9B9B9B`）: 「背景が透けた PNG の人物を重ねられます。人物は色の島に入れず、時刻になじませます。」
  - 二次ボタン「人物の絵を重ねる」。受け付けるのは `image/png,image/webp`。
- **人物があるとき**:
  - 1行目: 小さな見本（高さ 48px、`#272727` の台、角丸 8px）、ファイル名（拡張子を外す。今の絵の名前と同じ作り）、文字だけのボタン「外す」（`#9B9B9B`）。
  - 目盛り「大きさ」: 20〜120% の直線。標準の 70% がちょうど中央。出力欄は「70%」。
  - 目盛り「光のなじみ」: 0〜1 の折れ線。左半分を 0→0.8、右半分を 0.8→1 に割り当て、標準を中央に置く（ほかの目盛りと同じ考え）。出力欄の言葉は「なし・弱め・ふつう・強め・最大」（0、0〜0.8、0.8、0.8〜1、1）。2026-10-27 に「夜のなじみ」から改名（夜だけでなく、どの時刻の光にもなじませるため）。
- **透過の無い画像を選んだとき**: 「この画像には透けた部分がありません。背景が透けた PNG を選んでください。」を、今のエラーの見た目（Notice）で出し、人物は重ねない。判定は、アルファが 250 未満の画素が 1% 未満なら「透過なし」とする。
- 読み込み中は、今の絵の読み込みと同じく、人物の節の操作も `disabled` にする。

書き出しの横の文言と、画像を外へ送らない約束は変えない。人物の画像も端末の外へ送らない。

## 言葉

人物、人物の絵を重ねる、外す、大きさ、光のなじみ。「レイヤー」「前景」「アルファ」は画面に出さない（使い手の言葉ではない）。

## 受け入れの基準（試作）

| 領域 | 基準 | 確かめ方 |
|---|---|---|
| 元に戻る | 背景は、台本の始まりと終わりで元の絵と一致する。人物つきの描画は、始まりと終わりで同じになり、CPU で求めた「元の背景に、光を受けた人物を線形の光でアルファ合成したもの」と一致する（8ビットで差 1 以下） | Vitest と画面の検査 |
| なじみ 0 | どの時刻でも、人物の画素が素材のまま | Vitest |
| 明るさの範囲 | `E` が 0.3〜1.15、`C` の最大の成分が 1、人物の線形の値が 0〜1 に収まる | Vitest |
| 点滅 | 3つの台本 × 人物つき（試作の素材）で、書き出した MP4 が WCAG と ITU の両方に合格 | `flash-check` |
| 人物なし | 人物が無いときの動作と見た目が今と同じ（既存の検査が全部通る） | `npm run check` ほか既存の検査 |
| 操作 | 重ねる、外す、大きさ、光のなじみ、位置が、キーボードだけで使える。axe の違反 0。焦点が見える | 3ブラウザの検査 |
| README のループの道具 | `app/test/showcase-render.mjs` に、人物の画像、位置、大きさ、なじみを渡せる | 実行して確かめる |

見た目の良し悪しは、メインが試作の素材（透過の女の子と、女の子のいない背景。メインが ChatGPT で作って渡す）で判断する。採用は利用者が決める。
