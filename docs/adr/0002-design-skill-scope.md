# ADR-0002: 導入したデザインスキルの適用範囲

- 状態: 承認
- 日付: 2026-10-27

## 文脈

- 利用者の依頼で、`elayadesign/ai-design-skills`（MIT、upstream commit `a2735a3`、2026-10-26）の2つのスキルを `.claude/skills/` に入れた。
  - `landing-page-design`: LP の構成・コピーと、書体・余白・角丸・背景・アイコン・動きの厳しい規則
  - `design-to-motion`: 静止したデザインを、空の状態から読み込まれて各要素が動く HTML にし、MP4 と GIF に書き出す
- `landing-page-design` は説明文で、LP に限らず「あらゆる Web UI・コンポーネント・試作」に使うよう求めている。その規則には「背景にグラデーションを使わない」「背景は平らな色」「ダークモードの背景色はこの6色だけ」がある。
- このプロジェクトは色そのものが作品の中身になる。色の場やグラデーションを禁じる規則を作品の画面に当てはめると、作るもの自体が成り立たない。
- どちらのスキルも「利用者の明示した指示と規則がぶつかったら利用者が勝つ」と書いている。

## 決定

1. `landing-page-design` は次にだけ使う。
   - 宣伝用のページ（LP）
   - アプリの外枠（操作部品・メニュー・パネル）の書体、余白、角丸、動き、状態（hover・focus など）
2. 作品の画面（色の場、生成した色、グラデーション、色の動き）には `landing-page-design` を当てはめない。そこでの色と動きの規則は、調査（`docs/research/`）を根拠にした別の ADR で決める。
3. `design-to-motion` は、完成した画面を紹介する動画・GIF を作るときと、LP の機能紹介の区画に使う。作品そのものの動きの設計には使わない。
4. スキルの規則とこのプロジェクトの ADR がぶつかったら ADR を優先し、どの規則から外れたかを ADR に書く。
5. スキルの更新は自動では取り込まない。上流を読み直したうえで写し直す。

## 理由

- 色を主役にしたものを作るのに、色の使い方を汎用の LP 規則で縛ると、作品の中心が削られる。
- 一方、外枠の UI や LP には、このスキルの具体的な数値（余白の段、書体の段、動きの曲線）がそのまま役に立つ。

## 結果

- 良い点: 外枠の UI と LP に一貫した規則が入る。作品の画面は調査に基づいて自由に設計できる。
- 悪い点: 「どこまでが外枠か」の線引きが画面ごとに要る。迷ったら、その画面の色が利用者の操作や生成の結果か（＝作品）、操作のための飾りか（＝外枠）で分ける。
- 見直す条件: 作るものが決まり、画面の構成が分かったとき。

## 検討した他の案

- スキルの規則を全面に当てはめる: 上のとおり、作品の画面と矛盾する。
- `landing-page-design` を入れない: 利用者が試したいと言ったスキルなので外さない。
