# ADR-0007: 技術の構成

- 状態: 承認（2026-10-27、利用者が確認）
- 日付: 2026-10-27

## 文脈

- 作るものは、サーバーを持たない Web の道具（ADR-0003）。画像は端末の外に送らない。
- 重い処理は、ブラウザの中の3か所にある。
  - 読み込み時の前処理: パレットの抽出と Shepard の重み（ADR-0004）。試作で約 0.3 秒
  - 毎フレームの合成: WebGL2 のフラグメントシェーダ。1080p で 1ms 未満
  - 書き出し: WebCodecs と MIT のマルチプレクサ（ADR-0005）
- UI は「画像の読み込み、色の島と役割の一覧、台本の選択と調整、時刻のスライダー、書き出しのダイアログ」程度の規模。
- 実装の大半は Orca のワーカー（Codex、dsh）が書く（ADR-0001）。試作は素の JavaScript だった。
- 品質の検査には、すでに `tools/visual-qa`（Playwright と flash-check）がある。

## 決定

| 領域 | 選ぶもの | 理由 |
|---|---|---|
| 言語 | TypeScript（strict） | 色の計算と台本のデータの形を、型で守る |
| ビルドと開発サーバー | Vite | 速い。Web Worker とシェーダの読み込みを素直に扱える |
| UI | React | ワーカーのモデルが最も迷わずに書ける。描画のループは React の外に置き、React は操作のパネルだけを持つ |
| 外枠の見た目 | CSS 変数の設計トークン + Tailwind CSS | `landing-page-design` の余白・文字の段・動きの曲線を、トークンとしてそのまま持てる（ADR-0002 の範囲だけ） |
| 描画 | 素の WebGL2 | シェーダは小さく、ライブラリは要らない。試作のコードを引き継げる |
| 前処理 | Web Worker | 読み込みで画面を止めない |
| 書き出し | WebCodecs + `mp4-muxer` / `webm-muxer` / `gifenc`（すべて MIT） | ADR-0005 |
| 単体テスト | Vitest | 色の計算の基準値（OKLab）、重みの性質（非負・総和 1・補間）、台本の安全の見積もり |
| 画面とブラウザの検査 | `tools/visual-qa`（Playwright + flash-check） | 既存の道具を使い続ける |
| 書式と静的解析 | Biome | 1つの道具で速い |
| パッケージ | npm、版は固定 | 再現性 |
| 配置 | 静的なホスティング | サーバーが要らない。場所は公開の段階で決める |

- フォルダ: アプリは `app/`。試作（`experiments/`）は参照用に残し、アプリからは読み込まない。
- 状態: 画像、パレット、重み、役割、台本、時刻を1つのストアに置き、React と描画のループの両方から読む。台本の時刻は描画のループが持ち、React には間引いて伝える。

### 追記（2026-10-27、M1 の後）: 依存のライセンス

- M1 の adviser は、仕様の「MIT・BSD・Apache-2.0・ISC に限る」を厳密に守り、Vite 8 と Tailwind 4 を採らなかった。中で使う Lightning CSS が MPL-2.0、Autoprefixer が使う caniuse-lite が CC-BY-4.0 だったため。採った版は Vite 7.3.7、Tailwind CSS 3.4.19、React 19.3.1、Vitest 5.0.5、Biome 2.6.3、TypeScript 5.9.3。
- 方針を次のとおり明確にする。
  - **配る成果物に入るもの**（実行時の依存、フォント）は MIT・BSD・Apache-2.0・ISC、フォントは OFL に限る。
  - **ビルドのときだけ使う道具**（バンドラ、CSS の処理、データ）は、MPL-2.0 や CC-BY-4.0 でもよい。成果物に入らないため。
- いまの版で困ることは無いので、版はすぐには上げない。上げるのは必要が生じたとき。

## 理由

- 試作で確かめた心臓部（WebGL2 の合成、Worker の前処理、WebCodecs の書き出し）は、フレームワークに依存しない。だから UI の選択は、書き手（ワーカーのモデル）の慣れと、型の安全で決める。
- React と Tailwind は、ワーカーのモデルの学習データに最も多く、手戻りが少ない見込み。

## 結果

- 良い点: 試作のコードをほぼそのまま TypeScript に移せる。ワーカーが書きやすい。
- 悪い点: React と Tailwind の分、配る大きさが増える（道具としては問題にならない見込み）。
- 見直す条件: 描画のループと React の再描画がぶつかって、操作が重くなったとき。

## 検討した他の案

- Svelte: 小さく速いが、ワーカーのモデルの書き慣れが React より劣る見込み。
- 素の TypeScript だけ: UI の状態の管理を自前で書くことになり、台本の編集の画面が育ったときに重くなる。
- three.js などの描画ライブラリ: 1枚の画像を合成するだけなので要らない。
