# ADR-0009: 人物の絵を背景に重ねる（試作）

- 状態: 提案（試作を別の枝で作り、利用者が見てから採用を決める）
- 日付: 2026-10-27

## 文脈

- README のループのために、ChatGPT で萌え絵（色鉛筆の女の子と背景を1枚に描いた絵）を作って動かした（ADR-0008 の追記）。お祭りの絵では、夜に女の子の髪へ斑点が出て、提灯も沈んで濁った。
  - 斑点の原因: 色鉛筆の1本1本の線が、16色の代表色のうち別々の色に近い。そのため隣り合う線が、夜に違う色へ動く（ADR-0004 の方式の限界）。
  - 屋上の絵では斑点は出なかったが、夜に女の子の白い部分が空の色に染まって、半透明に見えた。
- 人物は、背景と同じ規則で色を移すと崩れやすい。人物の色は「空や水の役」ではなく、「その時刻の光を受ける物」として変わるのが自然である。
- 利用者の発案（2026-10-27）: 女の子と背景を別々に生成し、女の子は透過にして重ねる。

## 決定（試作の範囲）

1. 背景は今までどおり、島と台本で色をめぐらせる。
2. 人物は、透過の画像を1枚だけ重ねる。人物は島に分けず、時刻に「なじませる」だけにする。
   - 空の明るさの比で暗くする。
   - 空の色の変化の一部を足す。
   - 台本の始まりと終わりでは、元の人物と完全に同じにする。
   - 式は `docs/design/foreground.md`。
3. 計算は OKLab で行い、描画は今の WebGL2 の同じパスで行う（人物用のテクスチャを1枚足す）。
4. 書き出し（MP4、PNG）と点滅の判定には、人物も入る。
5. 人物を自動で切り抜く機能は入れない。切り抜きは、生成する側かほかの道具で行う。
6. 作るのは別の枝（`surumenDD/v02-foreground`）。main への合流と公開は、利用者が試作を見て採用を決めてから行う。

## 経過（2026-10-27）

- 試作は sol（adviser）が `surumenDD/v02-foreground` に実装した（`3f299db`、`4519f7a`）。報告は枝の `app/reports/V02-foreground-report.md`。
- メインの受け入れ: 枝で `npm run check` が通った（81件）。パネルの3つの状態（人物なし、人物あり、透過なしのエラー）が設計どおり。本物の機能でお祭りを書き出し、メインの式の見本と同じ見え方を確かめた。
- 式は、メインが素材で試した結果、基準色を上空と地平の平均に、なじみの標準を 0.8 に改めた（`docs/design/foreground.md`）。
- 利用者は、お祭りの重ねる版（浴衣の女の子 ＋ 女の子のいない背景）を README のループの第一候補にした。分ける前の絵の、女の子が手前に大きく立つ臨場感が惜しいとの指摘を受け、大きさ 105%、足元を絵の下へはみ出させる配置（x 0.5、y 1.26）を作った。
- 採用（main への合流と公開）は、利用者が試作のアプリを触って決める。それまで README は海辺の版のまま（重ねる機能が公開のアプリに無いうちは、重ねた絵を載せない）。

## 理由

- 人物の細かい質感を島に分けなければ、斑点は原理的に出ない。
- 「光を受けてなじむ」だけなら、式が単純で、始まりと終わりで元の絵に戻る約束（ADR-0004）も守りやすい。
- 背景と人物を別々に作れば、同じ人物をどの背景にも置ける。萌え絵の見せ方の幅が広がる。

## 結果

- 良い点: 人物が夜に崩れない。人物を変えずに背景だけ替えられる。
- 悪い点: 素材を2枚（透過の人物と背景）用意する手間が増える。人物と背景の光の向きや画風が合わないと、貼り付けたように見える。「夜のなじみ」の目盛りで調整する。
- 見直す条件: 試作を見て利用者が採らないと決めたとき。人物を2人以上にしたくなったとき。

## 検討した他の案

- 人物も島に入れる（今の方式）: 色鉛筆の人物で斑点が出た。
- 人物の島だけ分割して守る: 灯りの推定と、明るさが範囲を超える決まり（ADR-0004）に当たった（丘の絵で確かめた）。
- 1枚の絵から人物を自動で切り抜く: 範囲が大きく、依存も増える。
- 人物を全く変えない: 夜に浮く。目盛り「夜のなじみ」を 0 にすれば選べる。
