# ADR-0006: 安全とアクセシビリティの基準

- 状態: 承認（色覚の代わりの手段は、当事者に確かめてから細部を決める）
- 日付: 2026-10-27

## 文脈

- 調査（`docs/research/synthesis.md` 4節）:
  - 光過敏の基準の原文: ITU-R BT.1702-3 と WCAG 2.3.1。1秒に3回を超える点滅と、画面の 25% を超える面積の両方がそろうと危ない。WCAG は 10° の視野（1024×768 での 341×256 CSS px）ごとに面積を見る。飽和した赤も対象。
  - reduced motion の根拠は前庭障害。
  - 色覚の代わりの手段: 色と形・文字を併用する（Xbox の指針）。Hue の開発元は当事者の助言で記号の仕組みを作った。
- 道具: `tools/visual-qa/flash-check.mjs`（dsh MiMo が作成、メインがレビュー）。両基準を別々に判定する。
  - 最初の版は、別々の場所の点滅を合算して数え、ゆっくりした暗転を「1秒に30回」と誤判定した。場所ごとに数える形に直した（`tools/visual-qa/README.md` の解釈 13・14）。
  - テスト 11 件が合格。台本の 24 秒の動画2本は両基準で合格（場所ごとに最大 1 回/秒）。5Hz の全画面点滅は両基準で不合格。
- 色の表現（ADR-0004）では、重みが非負で総和が 1。そのため色域に収める前は、各画素の1コマの OKLab の変化が、パレットの各色の変化の最大値を超えない（`experiments/recolor-spike/NOTES.md` の「時間の連続性」）。

## 決定

1. **光過敏**
   - 書き出す前に必ず `flash-check` を通す。WCAG と ITU の両方で合格しないものは書き出さない。ITU の白の輝度は 200 cd/m² を既定にする。
   - 再生と書き出しは同じ台本と同じ描画で行う（ADR-0005 の決定的な描画）。だから、書き出しの判定がそのまま再生の安全を表す。
   - 使い手が台本を編集したときは、画像を描かずに、パレットの1コマの変化の上限から危ない点滅の可能性をその場で見積もる。危なければ、編集をその場で止めて理由を示す。見積もりの式と閾値は、実装の段階で `flash-check` の結果と突き合わせて決める。
   - 既定の台本の区間は、どれも 1 秒より十分長くする（今の台本の最短の区間は 1.4 秒）。灯りの揺らぎは周期 2 秒以上、振幅はごく小さく保つ。
2. **動きを減らす設定**
   - 自動再生しない。再生は使い手の明示した操作で始める（試作の方針をそのまま採る）。
   - `prefers-reduced-motion: reduce` のときは、元の絵か選んだ時刻の静止画を出す。時刻はスライダーで手動で動かせる。
3. **色覚の多様性**
   - 外枠の UI では、情報を色だけで伝えない。役割には文字の名前を付け、島の選択は輪郭と明暗でも示す。
   - 明暗だけの表示（色を除いた L の表示）を用意し、色の島と台本の流れを明暗でも追えるようにする。
   - 色覚のシミュレーションの表示は、補助として付けてよい。ただし、正確さを売り物にしない（Machado の実装の一つに、彩度の高い色で不正確になる誤りがあった）。
   - 細部は、当事者に確かめてから決める。
4. **品質の基準として機械で確かめる**: `flash-check` と、reduced motion で静止すること（`probe-eval` の reduced motion の画素差 0）を、テストに入れる。

## 理由

- 色が動くことがこの作品の中心だから、光過敏の安全は「気をつける」ではなく、構造と機械の検査で守る。
- ADR-0004 の表現のおかげで、安全の上限をパレットの動きだけから安く見積もれる。編集の途中でも確かめられる。

## 結果

- 良い点: 書き出したものと、画面で再生したものの両方が、同じ基準で守られる。
- 悪い点: 激しい点滅を意図した表現は作れない（作らない）。`flash-check` の判定は、等輝度の赤の切り替わりを取りこぼしうる（README の制限事項）。
- 見直す条件: 判定器の取りこぼしが見つかったとき。当事者に確かめて、色覚の代わりの手段が足りないと分かったとき。

## 検討した他の案

- 起動時に警告を出すだけ: 防ぐのではなく、責任を使い手に渡すだけになる。
- 書き出し後だけ判定する: 編集中に危ない台本を作れてしまう。
