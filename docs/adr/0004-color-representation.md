# ADR-0004: 色の表現 — OKLab のパレットと、固定の重みと差分

- 状態: 承認（重みの付け方は 2026-10-27 の追記で決定）
- 日付: 2026-10-27

## 文脈

- ADR-0003 の未知1「写真や階調のある絵でも、細部を壊さずに色を差し替えられるか」を、`experiments/recolor-spike/` で確かめた（Codex、4種類の絵 × 3方式）。
- 色の計算の根拠は `docs/research/synthesis.md` の 2節と 2b節。
  - Ottosson は CIELAB の青の色相の予測と、CAM16-UCS のブレンドの振る舞いを問題にした。
  - 色域に収めるときは、色相の変化が最も目立つ。
  - Chang ら 2015 は、ブラウザで対話的に動くことと、色域外と明るさの逆転という破綻を報告した。
- 試作の結果（`experiments/recolor-spike/NOTES.md`）:
  - 硬い量子化（各画素を最も近いパレット色に置き換える）は、空・水・筆致・雲の階調を壊した。再現の PSNR は 23〜29 dB だった。
  - 差分を保つ2方式は、パレットを変えないとき元の画像を完全に再現した（PSNR ∞）。式は `y = x + Σ w_k (Q_k − P_k)` で、x は元の OKLab、P は元のパレット、Q は編集後のパレット。
  - 重みを時間で変えないので、各画素の1フレームの変化はパレットの変化を超えない。割り当ての切り替わりによるちらつきは、原理的に起きない（同 NOTES の「時間の連続性」）。
  - 重みの付け方には、それぞれ弱点がある。
    - 最近傍の重み（1つの色だけに 1）: 狙った色にはっきり届くが、大きな変更で色の境に斑点が出る。
    - 正規化した Gaussian の重み: 斑点は抑えるが、変化が周りの色に漏れ、狙った色への到達が弱まる。
    - メインの目視（試験 b、平らな色面）では、最近傍の重みは紺→えんじに届き、Gaussian の重みは灰色がかった紫に薄まった。
  - 1080p での合成は、試した GPU で 1ms 未満。前処理は約 0.3 秒。

## 決定

1. **色の計算は OKLab / OKLCH で行う**。補間は OKLab の直線。色域の外に出た色は、L と色相を保ったまま彩度を下げて sRGB に収める（二分探索）。各チャンネルを切り捨てる処理は使わない。
2. **画像の表現は「パレット + 画素ごとの固定の重み + OKLab の差分」にする**。合成は `y = x + Σ w_k (Q_k − P_k)` を WebGL2 のフラグメントシェーダで毎フレーム行う。重みは画像を読み込んだときに1回だけ計算し、再生中は変えない。
3. **硬い量子化は既定にしない**。本物のドット絵（色数が少なく、格子のそろった絵）で、元の番号をそのまま保つ扱いが要るかは、別に決める。
4. **重みの付け方は、まだ決めない**。次の試作で、次の2つを両立する方法を探す。
   - 狙った色に届く: パレット色そのものの画素は、その色の重みが 1 になる補間の制約
   - 斑点が出ない
   候補は、補間の制約を持つ RBF（Chang ら 2015 の系統）、位置も使う重み（Tan ら 2018 の RGBXY の系統）、使い手が島を固定・分離する操作の3つ。

## 追記（2026-10-27）: 重みの付け方

`experiments/weights-spike/`（Codex、6候補 × 4枚 × 4試験）の結果を受けて、決定4を次のとおり決める。

- **基礎の重みは、補間の制約を持つ Shepard**（`w_k = d_k⁻⁴ / Σ_j d_j⁻⁴`、d は OKLab の距離）。非負で総和が 1、パレット色そのものの画素ではその色の重みが 1 になる。
  - 試験 b（最大の色の色相を +120°）の到達率は 4枚で 82〜92%。Gaussian は 35〜52%、補間 RBF は 52〜61% だった。
  - 斑点の指標は、最近傍より 25〜37% 少ない。
  - メインの目視（平らな色面の試験 b）でも、紺→えんじに素直に届き、この縮尺では斑点は目立たなかった。
- **島は「パレットの色 × 位置」で分ける**。色だけでは、離れた場所の同じ色（空と海の青）を分けられない。
  - 試験 e では、手で上下の領域を指定すると、空の到達 87%・海 0% で、同じ色番号の空と海を別々に動かせた。
  - メインの目視では、赤い空と青い海の一枚として成り立っていた。
  - 自動で「空だけ」を選ぶことはできず、山の上側も一緒に動いた。そのため、島の分割は使い手が直せる操作として作る。
- **空間の平滑化は既定にしない**。細かな粒は減るが、大きな雲状のむらとにじみを生んだ。
- **明るさを大きく変えると、L が範囲外に出る画素がある**（写真調の試験 d で 1,171 画素）。重みでは解けない。そこで、パレットの色を動かせる上限を、画素と重みから先に検査する設計にする。

残る問題: 大きな編集での細かな色むらは消えきらない。モバイルでのメモリと半精度化は未検証。

## 追記（2026-10-27、M2）: L の範囲外の扱い

- M2 の adviser の測定: 台本 v4 の初期設定のままでも、画像を描かずに上限で見積もると、見本の絵で 1〜75 画素（真っ黒か真っ白のまれな画素）の L が範囲外に出る可能性がある。厳密に拒否すると、見本の再生ができない。
- **決定**: L を [0,1] で止める（丸める）ことを、例外ではなく通常の処理として許す。ただし量で区切る。
  - どのフレームでも、丸めた画素が全体の 0.5% 以下
  - はみ出しの量が L で 0.08 以下
  - これを超える設定（例: 大きく黒い面を持つ絵で、夜の深さを強くしたとき）は受け付けない。スライダーは安全な端で止める。
- **理由**: 範囲外に出るのは、もともと真っ黒か真っ白の画素を、さらに暗く（明るく）しようとしたとき。止めても見た目はほぼ変わらず、失うのは最も暗い影の中のわずかな階調だけ。止めれば明るさの変化は小さくなる一方なので、光過敏の安全（ADR-0006）にも反しない。時間の中でも連続していて、ちらつきは生じない。
- 元のパレットのときは丸めが起きないので、元の画像の再現（PSNR ∞）は保たれる。

## 理由

- 差分を保つ表現なら、元の絵が必ず出発点になる。使い手の絵を壊さないことは、この道具が使い手に約束できる最低限の品質。
- 重みを固定すれば、時間の中のちらつきを測定ではなく構造で防げる。光過敏の基準（P7）を守るうえでも有利。
- 重みの付け方は、到達と斑点の両立が未解決なので、ここで決めると後で縛りになる。

## 結果

- 良い点: パレットの変化だけで、画像全体の色を毎フレーム安く動かせる。元の画像の再現は代数的に保証される。
- 悪い点: 重みと元画像の OKLab を GPU に持つので、メモリが要る（試作では 1.57MP あたり 72MiB）。半精度化と重みの圧縮は未検証。
- 見直す条件: 次の試作で、到達と斑点を両立する重みが見つからないとき。モバイルでメモリが足りないとき。

## 検討した他の案

- 硬い量子化（インデックスカラー）: 古典的なカラーサイクリングの方式。ただし、階調のある絵を壊す。
- 画像全体に LUT（色の対応表）を当てる: 色の島を個別に動かせない。そのため、P4（置き方と動かし方）の道具にならない。
