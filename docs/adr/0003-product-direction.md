# ADR-0003: 作るもの — 色を時間に置く道具

- 状態: 承認（方向と目的。機能の範囲と技術は、下の未知を試作で確かめてから別の ADR で決める）
- 日付: 2026-10-27

## 文脈

- 調査（`docs/research/synthesis.md`）から、次の原則を引いた。
  - 急がせない・採点しない（P1）
  - 買い切り・広告なし（P2）
  - 色の選び方より、置き方と時間の中の動かし方（P4・P5）
- 時間の中の色を中心にした有料品は、調べた範囲では見つからなかった。
- 3モデルの案9つを4つの方向に束ねた（`docs/ideation/README.md`）。チームに絵を描く人がいないため、素材の制作の重さが方向を分ける。
- 2026-10-27 に利用者と次を決めた。
  - 方向: B「色を時間に置く道具」
  - 目的: まず Web で作品として公開し、反応を見て、手応えがあれば買い切りの製品にする
  - 素材: 利用者は絵を描けるが時間がかかるので、ひとまず高品質な代案（ChatGPT の画像生成、手続き生成）で進める

## 決定

使い手の絵や写真を持ち込むと、形はそのままに、色だけが時間の中で巡る作品になる。それを作る Web の道具を作る。案の原型は DeepSeek の「色回し」（`docs/ideation/dsh-deepseek-v4.1-flash.md` の案2）。

体験の芯:
1. **最初の30秒**: 見本の絵が、色だけで巡っている。自分の画像を落とすと色の島に分かれ、すぐにループが始まる。
2. **最初の10分**: 島を直す。区間の長さをそろえずに決める（P5）。全体の色の移り変わり（カラースクリプト）を引く。ループを書き出す。
3. **既定の時間設計の質で勝負する**。Ferrari の1日の光の循環、Turrell の薄暮のように、作り手の知恵を既定値に込める。「安い GIF の効果」に見えるのが最大の危険なので、その対策をここに集める。

守ること:
- 画像は端末の外に送らない（ブラウザの中だけで処理する）。
- 調和スコアを出さない（P6）。
- 光過敏の基準を数値で守る（P7）。
- 色覚の多様な人の代わりの手段を最初から入れる（P8）。

作らないもの（最初の公開まで）:
- アカウント、クラウド保存、共有の仕組み
- 絵を描く機能
- 決済（製品化の段階で別に決める）

## 理由

- 素材が使い手の絵なので、絵を描く人がいなくても成り立つ。
- 中心の仮説（色は置き方と時間の中の動かし方で芸術になる）を、最も小さく確かめられる。
- 心臓部は、方向 A（生きた一枚絵）と D（色彩暦）でも使い回せる。心臓部とは、色の島への分割、OKLab で溶かしながら回す処理、周期のそろわない循環である。

## 結果

- 良い点: 最初の試作まで近い。公開して反応を見る段階で、決済や配布を作らずに済む。
- 悪い点: 出来が使い手の絵に左右される。既定の時間設計が弱いと、ただのエフェクトに見える。
- 確かめるべき未知（試作で答える）:
  1. 色の島への分け方。写真や階調のある絵でも、細部を壊さずに色を差し替えられるか。パレットに基づく画像の分解と色の差し替えの研究を調べる。
  2. 書き出し。ブラウザだけで、ループする動画と GIF を十分な質で書き出せるか。
  3. 安全の検査。光過敏の基準を、書き出す前に機械で確かめられるか。
  4. 見本の絵の質。生成した絵で、最初の30秒の印象を作れるか。
- 見直す条件: 未知1が解けないとき（島が汚い、細部が壊れる）。公開後の反応が弱いとき。

## 検討した他の案

- A. 生きた一枚絵: 絵の作り込みが命で、素材の制作が最も重い。心臓部が共通なので、B の後に見本の絵を作品化する形で取り込める。
- C. ゲーム（光のせい、ときのいろ、色の劇場）: 新しさは最も高いが、部屋や幕ごとの作り込みが重く、試作まで遠い。
- D. 色彩暦: 最も新しいが、露出を固定した撮影が要り Web では難しい。価値が見えるまで時間がかかる。
