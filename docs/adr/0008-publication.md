# ADR-0008: 公開の方針 — 公開リポジトリ、すべて MIT、無料のサイト

- 状態: 承認（公開リポジトリの作成と push は、準備と点検の後に利用者の確認を取って行う）
- 日付: 2026-10-27

## 文脈

- 目的は、まず作品として Web に公開して反応を見て、手応えがあれば製品化すること（ADR-0003）。
- 『ひとめぐり』はサーバーを持たない静的な Web アプリ（ADR-0007）。画像は端末の外に送らない。
- 調査では、写真を動かすアプリが書き出しを有料の壁にし、サブスク化への不満が強かった（`docs/research/synthesis.md` 4b節）。
- 公開の候補（2026-10-27 に利用者へ示した）: Cloudflare Pages、GitHub Pages、Netlify / Vercel、itch.io、独自のドメイン。
- 利用者の判断（2026-10-27）: public で無料で公開する。リポジトリも公開し、ライセンスは**すべて MIT**（コード、見本の絵、台本の数値、文書のすべて）。
- 手元の状況: このリポジトリはまだ GitHub に無い（リモートなし）。コミットの作者は GitHub の noreply のアドレスだけ。

## 決定

1. **サイトは無料で公開する**。公開先は **GitHub Pages**（公開リポジトリなら無料。GitHub Actions でビルドして配る）。
2. **リポジトリを公開する**。ライセンスは MIT を1つ、リポジトリの直下に置く。見本の絵と台本の数値も含む。
3. 第三者のものは、それぞれのライセンスのまま扱い、表示する。
   - フォント: Zen Kaku Gothic New（OFL）
   - npm の依存（`app/public/THIRD-PARTY-LICENSES.txt`）
   - `.claude/skills/` の2つのスキル（MIT、elayadesign、各フォルダに LICENSE）
4. 見本の絵が画像生成（ChatGPT）で作ったものであることを、README とサイトの説明に書く。生成物の著作権は国や地域で扱いが定まっていないので、MIT は「こちらが持つ権利の範囲で」許諾するものとする。
5. **公開の前に点検する**（M4）。
   - 履歴の全体に、秘密の情報（API キー、トークン）が無いことを機械で走査する
   - 文書に出ている手元のパス（`C:\Users\ryo52\...`）を残すか、利用者と決める
   - 調査の原文（`~/research/`）はリポジトリの外にあり、入れない。`docs/research/synthesis.md` の短い引用は、出典を示した引用として残す
6. **公開リポジトリの作成と push は、利用者の確認を取ってから行う**。一度公開すると、複製や保存をされて取り消しが利かないため。リポジトリの名前は、そのときに利用者と決める（候補: `hitomeguri`）。
7. **名前と見せ方**（2026-10-27、利用者の判断）:
   - リポジトリ名は `hitomeguri-color`。サイトは `https://surumenDD.github.io/hitomeguri-color/`（Vite の `base` を `/hitomeguri-color/` にする）。
   - リポジトリの見せ方: 説明文、サイトの URL、トピック、README の冒頭のループの GIF、social preview の画像（1280×640。アップロードは画面でしかできないので利用者が行う）。
   - GitHub のプロフィールの Overview: ピン留め（利用者が画面で、今の6件の1件と差し替える）と、プロフィール README（`surumenDD/surumenDD` を公開で作り、ループの GIF とサイトへのリンクを置く。作る前に利用者の確認を取る）。
   - ループの GIF は、`design-to-motion` の書き出しの仕様（800×500、20fps、軽さ優先なら 12fps）に沿って作る。
   - 2026-10-27 追記（M4）: ループは GIF をやめ、**動く WebP** にした（`docs/showcase/hitomeguri-800x500.webp`、4.7MB）。この絵は1コマごとに全面の色が変わるので、GIF の圧縮が効かない（800×500、12fps の GIF で 66MB）。WebP も1コマずつ丸ごと記録するので、容量はコマ数に比例する。そこで1日を2倍の速さ（12秒）、10fps、画質 88 にした（画質 70 では夜の空にブロックが出た）。2倍の速さでも点滅の検査（WCAG と ITU）に合格する。作り方は `experiments/brand/loop.sh`（後に `reel.sh` へ置き換え）。
   - 2026-10-27 追記（公開後）: ループを「1人目の萌え絵のお祭り → 雪の村」の2場面にした（**暫定**、利用者の判断）。1場面14秒で1日をめぐり、場面の間とループの継ぎ目は 0.8 秒だけ暗く沈めて移る。7fps、画質 80、7.0MB。点滅の検査は WCAG と ITU の両方に合格。萌え絵の素材と生成の経緯は `assets/showcase/`、作り方は `experiments/brand/reel.sh`。見比べた候補（色の帯つき、4枚を並べる、4場面を続ける版など）と、9秒は速すぎたこと、女の子と背景を分けて生成し女の子を透過で重ねる案（次の版の候補）は、利用者とのやり取りで出た。
   - 同日、上の暫定版は取り下げて運河の版に戻した（利用者「画質がめちゃくちゃ悪い」）。主な原因は圧縮ではなく色の移し替え: 色鉛筆の細かい線が16色の別々の代表色に近く、隣り合う線が夜に違う色へ動いて斑点になる。さらに提灯が「灯り」と推されず、夜に提灯ごと沈んで濁る。WebP はその斑点を潰して塊にした。ざらつきを輪郭を残してならす前処理（バイラテラル）で斑点は消えたが、提灯の問題は残った。細かい質感の絵への対応（重みを空間でならす、灯りの推定）は次の版の課題。
   - 同日、ループを「海辺の女の子 → 雪の村」にした（**暫定**、利用者の判断）。海辺は絵全体が同じ色鉛筆のタッチで、女の子の色が空と近いので、夜も斑点が出ずに一緒に沈む。島15（沈む夕日と一番星）だけ「空」に直した。画質は 85（80 では色鉛筆の線と夜の顔がならされた。元の大きさで比べて決めた）、9.7MB。点滅の検査は合格。女の子と背景を分けて重ねる機能は別の枝で作り、利用者が見てから採用を決める。
8. 製品化は、手応えを見てから決める。その時の道の候補は、itch.io での投げ銭や買い切りの配布。MIT でも、作り込んだ見本の絵と台本、手軽さ、作り手への支援として売れる余地がある。
9. **公開前の点検の結果**（2026-10-27、利用者の判断）:
   - 手元のホームの絶対パス（8ファイル10か所、どれも実験と検査の記録の中）は、そのまま残す。
   - Codex の能力の記録に並んでいた、接続したアプリと MCP のツールの一覧（4行）は、**履歴ごと消した**（git filter-repo、公開用の複製の上で）。中身が変わったのはそのファイルだけ。番号が変わったコミットの対応は `docs/commit-map.md`。

## 理由

- 無料で誰でも触れることが、「作品として公開して反応を見る」に最も合う。書き出しを有料の壁にしない立場は、調査で見えた不満への答えにもなる。
- ADR・調査・マルチエージェントでの作り方そのものが、作品の裏側として読める。
- すべて MIT は利用者の判断。広がりやすさを最大にする代わりに、複製を売られても止められないことを受け入れる。

## 結果

- 良い点: 費用 0。誰でも使え、作り方も学べる。
- 悪い点: そっくりな複製が作られても止められない。製品化の差は、作り込みと手軽さで出すことになる。
- 見直す条件: 製品化を決めたとき（配布の場所と売り方を別の ADR で決める）。

## 検討した他の案

- コードは MIT、絵と台本は権利を保持: メインの推奨だったが、利用者はすべて MIT を選んだ。
- リポジトリは非公開、サイトだけ公開（Cloudflare Pages）: 作り方を見せない。利用者の「public で」に合わない。
