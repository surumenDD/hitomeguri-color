# 案出しのまとめ

3モデルに同じ下地（`docs/research/synthesis.md`）を渡し、互いの案を見せずに3案ずつ出してもらった。原文は同じフォルダの3ファイル。ここではメインが束ねて比べる。

## 9案を4つの方向に束ねる

| 方向 | 案（出したモデル） | 一言 |
|---|---|---|
| **A. 生きた一枚絵**（鑑賞） | 一枚の夕暮れ（Codex 推し）、ながれえ（MiMo） | 形は動かず、色だけが1日の光のように巡る絵を、手元に置く・飾る |
| **B. 色を時間に置く道具**（作り手向け） | 色回し（DeepSeek 推し）、色の編集机（Codex）、にぶらし（MiMo 推し） | 自分の絵の色を回す／作品のカラースクリプトを組む／並べ方を確かめる |
| **C. 色が時間で巡るゲーム** | ときのいろ（MiMo）、色の劇場（Codex）、光のせい（DeepSeek） | 時刻を合わせて解く／色を手渡して絵を変える／照明か塗料かを見分ける |
| **D. 色で記録する** | 色彩暦（DeepSeek） | 同じ窓の光を1年ためて、色の帯の映画と本にする |

## 収束と、その割り引き

- 9案のうち8案が「形は動かさず、色を時間の中で動かす」を中心にした。
- これは調査の結果でもあるが、メインが synthesis.md の 3節に「時間の中の色を中心にした有料品は見つからなかった」と書いたことに引っ張られた面がある。DeepSeek は「そこが空いている場所だと考えた」と明記している。収束を、そのまま独立した3票とは数えない。
- 3モデルのうち2つが、最初の1本に「いちばん小さい案」を推した（Codex: 一枚の夕暮れ、DeepSeek: 色回し）。理由はどちらも「中心の仮説（P4・P5）を最も安く確かめられる」。

## メインの評価

軸は、調査の原則に合うか、絵の素材を誰が作るか（チームに絵を描く人がいない）、最小の試作までの距離、新しさ、芸術性の天井。売れるかどうかは、どの案も推測の域を出ない。

| 方向 | 原則との合い方 | 素材の制作 | 最小の試作まで | 新しさ | 芸術性の天井 |
|---|---|---|---|---|---|
| A. 生きた一枚絵 | 高い（P1・P4・P5） | **重い**。Ferrari の言うとおり、絵とパレットの両方の作り込みが要る。手続き生成の絵で代えられるかは未知 | 近い | 中 | 高い（絵の質しだい） |
| B. 色を時間に置く道具 | 高い（P4・P5・P6） | **軽い**。素材は使い手の絵 | 近い | 中〜高 | 使い手の絵しだい。既定の時間設計の質が差になる |
| C. ゲーム | 中（P1 と「解く」が緊張、P8 が難しい） | **最も重い**。部屋や幕ごとに作り込み | 遠い | 高い（特に「光のせい」） | 高い |
| D. 色で記録する | 高い | 軽い（素材は使い手の写真） | 中。露出を固定した撮影が要り、Web では難しい | **最も高い** | 中〜高 |

方向 A・B・D は、同じ心臓部を共有する。具体的には次の3つ。
- 画像を色の島に分ける処理
- OKLab で色を溶かしながら回す処理（BlendShift）
- 周期のそろわない複数の循環と全体のカラースクリプト

心臓部を1つ作れば、方向を変えても使い回せる。

## 決めること（利用者と）

1. どの方向を最初の1本にするか
2. 絵の素材をどうするか（利用者が描く、手続き生成、使い手の画像）
3. 目的（売る製品か、公開する作品か）

プラットフォームは、決めるまで Web を前提に進める。試作と共有が最も速く、導入したスキル（`design-to-motion`）とも合う。
