# アイデア3案（dsh-mimo-v2.6-pro）

- 対象: 「色で何かができる、視覚的なデザインと芸術性に優れたもの」の案を3つ。
- 根拠: `docs/research/synthesis.md`（4調査の知見と設計原則 P1〜P9）。調査に無い事実を足した箇所には出典 URL か「推測」を付ける。
- 構成: 案1 = いちばん大胆な案、案2 = いちばん小さく出せる案、案3 = 自由。各案に見出し1〜9、最後に推す案と理由。

## 案1（いちばん大胆）『ときのいろ』— 色が時間で巡る世界を「時刻」で解くパズルアドベンチャー

### 1. 名前（仮）と一文の説明
『ときのいろ』（Toki no Iro）。ピクセルは動かず色だけが巡る世界を、「消える時刻」を合わせながら進む、急がせないパズルアドベンチャー。

### 2. 誰が、いつ、どこで使うか
- 色や絵が好きな人、パズルは好きだが時間制限が苦手な人（synthesis §1 の「急がされずにじっくり考えられる」を求める層）。
- 夜のくつろぎの30分、週末の午後。据え置き機・ゲーミングPC・タブレット（推測: 一枚絵の見どころから、画面の大きい機器が向く）。

### 3. 体験の流れ（最初の30秒、最初の10分、1か月後）
- 最初の30秒: 薄暮の一枚絵。色がゆっくり巡る。操作は「時間のつまみ」だけ。つまみを回すと絵の色がまるごと時巡りする。
- 最初の10分: 「壁と同じ色になった瞬間に消える橋」の最初の3問。つまみで時刻を探し、消えた橋を渡る。カウントダウンも点数も無い（P1）。音は Color Zen と同じく成功の手応えとして薄く入れる（§1）。
- 1か月後: 章ごとに「周期の違う2つの仕掛けを合わせる」等の新しい時刻の問題が増える。終盤は章全体の色の移り変わりが物語の幕になる（Pixar のカラースクリプトに相当する設計を、ゲーム全体の色の流れとして先に作る: §3）。

### 4. 色が何をするか（どう置き、時間の中でどう動くか）
- ピクセルは静止し、パレットだけがループする（Ferrari のカラーサイクリング: §3）。絵は層つきインデックス画（空・水・灯りなど）として描き、層ごとに周期と位相を変える。
- 循環の長さと速さはそろえない（P5）。例: 空=11分、水=7分、灯り=3分。周期が重なる時刻だけ「扉が開く一瞬」になる。
- 補間は OKLab。RGB 補間で中間が灰色にすむのを避け、HSL の 0°/360° の飛びも出さない（P3、§2）。色域から外れるときは色相と明度を保ち彩度を下げる。
- 章の色の流れ（どの場面でどの色に寄せるか）を先に決め、部屋の設計はそれに従う（§3 の「半分は着想で、半分は連続性」）。

### 5. 原則 P1〜P9 のどれをどう満たすか。どれと緊張関係にあるか
- P1: 満たす。タイマーではなく時間のつまみで、巡る速さの主導権をプレイヤーに渡す。
- P2: 満たす。買い切り・広告なし。
- P3: 満たす。OKLab 補間と色域マッピングをエンジンで固定する。
- P4: 満たす。解は「どの色か」ではなく「いつ」にあり、置き方と時間の動かし方がそのまま遊びになる。
- P5: 満たす。周期の不揃いが仕組みの核。
- P6: 無関係（採点しない）。
- P7: 満たす。循環速度に上限を置き、reduced-motion では自動で回さずつまみ操作のみ。明暗差は ITU の物差しで機械検査する（§4）。
- P8: 満たす。色に加えて形・模様・音でダブルエンコードし、つまみに時刻の目盛りを付ける（Blendoku 2 と Hue の symbol system: §1）。
- P9: 緊張。ゲームの中心に「色が背景と一致すると消える」知覚現象を置くのは Hue と同じ土俵。混ぜる規則は入れないが、彩度が極端な色での見え方の個人差（推測）が、同じ種類の「例外で混乱」を生みうる。
- P5 と P1 にも緊張: 周期をずらすほど「合わせる時刻」が遠くなり、待ちが長くなる。つまみと部屋ごとの位相調整で逃がすが、設計次第で「待たされる」体験に落ちる。

### 6. synthesis.md の1節に出てくる既存品との違い
- Hue: 背景色をプレイヤーが選び、色で物を消す。平らな1色の背景が必須（§1）。本作は色を選ばせず、時間で合わせ、密度のある一枚絵が残る。
- I Love Hue / Blendoku: 静止した色の並べ替え・順序づけ（§1）。本作は色が動く。
- Color Zen: 同色をぶつけて背景色を変える遊びで、時間軸が無い（§1）。
- Specimen: 「もう一度初心者になって成長を感じる」作画体験（§1）。本作は作らず、巡りを見る。
- Coolors / Sip / Pantone Connect / ibisPaint / Procreate: 色を選ぶ・描く道具（§1）。本作に色を選ぶ UI は無い。

### 7. 売り方
- 買い切り・広告なし（P2）。サブスクにしない（§1 の反発の根拠）。
- 売り場は PC ストアとコンソール（推測: くつろぎの30分という使い方に合う）。
- 価格は $15〜20 前後（推測。Sip の $10、Coolors の年 $36、Pantone Connect の月 $15（§1）の並びから見てゲームの相場感で置く）。第1章だけを広告の代わりの体験版にする（推測）。

### 8. 技術の芯（いちばん難しいところと、最初に作るべき最小の試作）
- いちばん難しい: 層つきインデックス画＋パレット循環の描画系と、「周期が違う仕掛けでも必ず解ける」ことの保証。部屋ごとに位相を設計し尽くすしかなく、検算はほぼ手作業になる（推測）。
- 最小の試作: 320×200 のインデックス画1枚（空・水・灯りの3層）を OKLab でパレット循環させるデモ＋時間のつまみ1本＋「消える橋」1問。2週間で「巡る絵」と「合わせる遊び」の両方が見えた時点で継続を判断する（推測）。

### 9. 失敗しそうなところ
- 「待つパズル」が退屈になるのが最短の失敗。つまみで逃がしても、巡る速さの設計を誤ると §1 が嫌う「急がされる／退屈」の両方に落ちる。
- Ferrari の教訓どおり絵とパレットの両方を作り込まないと効果が出ず（§3）、ピクセルアートの制作がボトルネックになる（推測）。
- CVD の人にとって「色の一致＝消える」の判断が難しい。P8 のダブルエンコードが間に合わないと根の部分で遊べない人が出る（Blendoku の教訓: §1）。

## 案2（いちばん小さく出せる）「にぶらし」— 並べた色が、目を細めて構造を保つかを見る1画面の道具

### 1. 名前（仮）と一文の説明
「にぶらし」（NIBURASHI）。色片を小さな盤面に並べて、目を細めたときに構造が残るかを確かめる、ブラウザの1画面だけの並べ方の道具。

### 2. 誰が、いつ、どこで使うか
- イラスト・デザインの作り手、配色を学ぶ学生・独学者。色を決める最後の5分、作業の合間。デスクトップのブラウザ1タブ（推測: 色の作業は画面が大きい場面が多い）。

### 3. 体験の流れ（最初の30秒、最初の10分、1か月後）
- 最初の30秒: 和田三造の348配色の JSON（MIT、§3）か自分の hex を貼った色片が盤面に出る。ドラッグで置くだけ。機能はこれと「にぶらし」ボタンだけ。
- 最初の10分: 「にぶらし」ボタンで全体がぼやけ、構造が残るかを見る（Hobbs の目を細める確かめ方: §3）。「同じ色の塊」表示で隣り合う同色を可視化して塊を育て、OKLab の L による明度の階段（P3）を横に置く。
- 1か月後: 自分の並べ方の作例が並び、書き出した PNG を実作業に持ち込む。道具の中で「並べ方の癖」が変わっていくのを体感する。

### 4. 色が何をするか（どう置き、時間の中でどう動くか）
- 置き方: 要素ごとの乱数の色を避け（§3）、同じ色の塊を作り、親の色を子が高い確率で継ぐ（Hobbs: §3）ことを盤面が誘導する。色そのものは生成しない。
- 時間: 「1日の光」モードで、並べた構成を朝→昼→夕→夜の光の下にゆっくり流し見する。夕暮れを最良の確認時刻として推す（Turrell: §3）。光の移り変わりそのものは先に設計した1本の流れに固定する（P5）。明滅は入れない（P7）。

### 5. 原則 P1〜P9 のどれをどう満たすか。どれと緊張関係にあるか
- P1: 満たす（時間制限も点数も無い）。P2: 満たす（買い切り・広告なし）。P3: 満たす（明度の階段と補間に OKLab を使う）。
- P4: 満たす（パレット生成ではなく、置き方と時間での見え方が本体）。P5: 一部（1日の光の流れを先に決める）。
- P6: 満たす。調和スコアを出さない（§2 の結論どおり、自動採点は根拠が弱い）。むしろ「点数が欲しい」という要望を断る緊張がある。
- P7: 満たす（にぶらしのぼかしは静止した表示。reduced-motion 対応）。
- P8: 満たす（Machado の CVD シミュレーション表示と明度の階段で、色相に頼らない物差しを用意: §4）。
- P9: 無関係（色を混ぜない）。
- 緊張: P4 の「時間の中の動かし方」は薄くしか持たず、大胆さに欠ける。単機能の道具としての価値の小ささと表裏一体。

### 6. synthesis.md の1節に出てくる既存品との違い
- Coolors / Pantone Connect: パレットを生成・管理する道具で、生成の自動化に不満と価格の文句が出る（§1）。にぶらしは生成せず、渡された色の並べ方だけを見る。
- Sip: 色を拾う道具（§1）。並べ方は扱わない。
- ibisPaint / Procreate: 何でも描ける（§1）。にぶらしは描けない。並べ方の確認だけに絞る。
- Hue / Specimen / Color Zen / Blendoku / I Love Hue: 遊びや作品提示（§1）。にぶらしは作り手の作業道具。

### 7. 売り方
- 買い切り・広告なし（P2）。アカウントを立てない買い切りライセンス（キー）で売る（推測: 静かな道具に合う売り方）。
- 価格は $10 前後（Sip の例: §1）、日本円で 1,000〜1,500 円（推測）。閲覧と配置は無料で、書き出し PNG と「1日の光」モードだけ買い切りにする（推測）。
- 見せ方は「同じ色を並べた2枚のにぶらし比較」の静止画1枚で足りる（推測）。

### 8. 技術の芯（いちばん難しいところと、最初に作るべき最小の試作）
- いちばん難しい: 「にぶらし」が本当に並べ方の判断に効くかの手応え。補間やグラデーションの色空間を人の評定で比べた研究は見つかっておらず（§2）、根拠は薄い。小さく比べるしかない（§6）。
- 最小の試作: 盤面・ドラッグ・にぶらしボタン・明度の階段だけを入れた HTML 1枚。自分の実作業で数日使って、並べ方が本当に変わるかで続けるかを決める（推測）。

### 9. 失敗しそうなところ
- 「見て終わり」の機能1個の道具は買われない可能性（推測）。売る価値は書き出しと1日の光モードに掛かる。
- にぶらしの効果が体感で薄いと、存在理由そのものを失う。
- CVD シミュレーションは Machado 実装の彩度の高い色での不正確さという既知の問題があり（§4）、正確さを売りにすると壊れる。

## 案3（自由）『ながれえ』— 24時間の光を閉じ込めた「生きた絵」をつくる・飾るスタジオ

### 1. 名前（仮）と一文の説明
『ながれえ』（Nagaree）。一枚のピクセル画に1日の光の移ろいを仕込み、絵は動かず色だけが巡る「生きた絵」を作る・飾る道具（ネイティブアプリ＋常駐表示）。

### 2. 誰が、いつ、どこで使うか
- 生成アートやドット絵の作り手、部屋に静かに動く絵を飾りたい人。制作は週末の数時間、鑑賞は就寝前や仕事中の背景（推測: アンビエント用途は常時表示に向く）。デスクトップで作り、タブレットや古い画面に飾る（推測）。

### 3. 体験の流れ（最初の30秒、最初の10分、1か月後）
- 最初の30秒: 用意された「板」（層つきインデックス画の下絵）と、朝・昼・夕・夜の4パレット。再生すると24時間の循環が1分に圧縮されて流れる。
- 最初の10分: パレットの色を差し替え、層ごとに周期と位相をずらす。夕暮れの一秒を決める（Turrell: §3）。色の移り変わり全体を先に決めてから細部を直す（§3 のカラースクリプト）。
- 1か月後: 自分の板と循環が数枚たまる。loop 動画を書き出したり、常駐表示に置いて1日ごとに巡らせたりする。

### 4. 色が何をするか（どう置き、時間の中でどう動くか）
- 置き方: パレットは層（空・水・石など）ごとに割り当て、同じ色の塊を保つ（Hobbs: §3）。要素ごとの乱数の色は使わない（§3）。
- 時間: 層ごとに周期を変える（例: 空=24時間、水面=9時間、灯り=2時間）。「同じ長さ・同じ速さの循環だけでは非常に硬く見える」（Ferrari: §3）を構造に組み込む。
- 補間は OKLab。RGB 補間の中間の灰色のくすみと HSL の色相の飛びを避ける（P3、§2）。「色を隣へ溶かしながら回す」BlendShift（Huckaby: §3）は、溶かさないモードと並べた選択式にする。
- 光の急な変化は ITU の物差しで機械検査する（P7、§4）。

### 5. 原則 P1〜P9 のどれをどう満たすか。どれと緊張関係にあるか
- P1: 満たす（速さは見る人の前でだけ決まる）。P2: 満たす（買い切り・広告なし）。
- P3: 満たす（エンジンの中心が OKLab 補間と色域マッピング）。
- P4: 満たす（作っているものが、色の置き方と時間の中の動かし方そのもの）。
- P5: 満たす（層ごとの周期の不揃いと、先に作る色の流れが本体）。
- P6: 満たす（調和スコアも自動採点も出さない: §2）。
- P7: 満たす（reduced-motion では静止画モードに。明滅は機械で検査）。
- P8: 一部。CVD 表示は付けるが、色が主役の鑑賞体験の代わりの手段は §4 でも調べ中で、確約できない。
- P9: 緊張。BlendShift は「色を混ぜる」を含む。Hue の作者の失敗（例外が多く混乱: §1）と同じ穴を避けるため、例外の無い設計の検証が先に要る。
- P8 と「色そのものを味わう体験」も本質的に緊張する。模様のダブルエンコードは絵の密度と衝突しうる（推測）。

### 6. synthesis.md の1節に出てくる既存品との違い
- Procreate / ibisPaint: 静止画を描く道具で、機能の有料化や作業中の広告に不満が出る（§1）。ながれえは成果物が「時間が動く絵」で、筆そのものを持たない。
- Specimen: 完成した作品とその提示（§1）。ながれえは制作環境と常駐表示をセットで持つ。
- Coolors / Sip: パレットの発見・保存（§1）。ながれえはパレットを時系列に編む。
- Hue / Color Zen / Blendoku / I Love Hue: 解く遊び（§1）。ながれえは作って飾るもので、正解も無い。

### 7. 売り方
- 買い切り・広告なし（P2）。アプリの買い切り＋板（下絵）の追加パックも買い切り。サブスクと既存機能の後からの有料化はしない（§1 が最も嫌う二つ）。
- 価格はアプリ $20 前後、板パック $5 前後（推測。Sip $10・Coolors 年 $36・Pantone Connect 月 $15（§1）の並びからの相場感）。
- 見せ方は24時間の循環を1分に圧縮した動画1本（推測）。静かな体験なので、広告ではなく作品の動きで売る。

### 8. 技術の芯（いちばん難しいところと、最初に作るべき最小の試作）
- いちばん難しい: 絵とパレットの両方を作り込まないと効果が出ない（Ferrari: §3）という制作コストと、層つきインデックス画の「板」フォーマットを成立させるか。技術より制作の設計が難しい（推測）。
- 最小の試作: 板1枚・層3つ・OKLab パレット循環・層ごとの周期設定・loop 動画の書き出し、まで。編集 UI は作らず、まず自分の手で板を3枚作って効果を見る（推測）。

### 9. 失敗しそうなところ
- 「背景に流すだけ」だと価値が伝わらず、§1 の人が払う理由（作る楽しさ・落ち着き）のどちらにも届かない。
- 板を量産できる制作力が続かないと、製品が1枚の絵に依存して終わる（推測）。
- BlendShift などの混ぜる演出は、Hue の2か月の失敗（§1）と同じく、例外の多さで混乱を招きやすい。

## 3案のうち、自分なら何を推すか

推すのは案2「にぶらし」。理由は次の5行。

1. 2〜3週間で出せて、P4 の主張「並べ方がパレット選びより大事」（§3）を実物で確かめられる。
2. 失敗しても失うものが小さく、残るのは検査の物差し（にぶらし・明度の階段・P7 の visual-qa 経験）で、次の案に全部持ち込める。
3. 案1・案3 は絵とパレットの両方の作り込みが要る（§3）ので、その前に「並べ方は効く」という手応えが欲しい。
4. 買い切り・広告なし（P2）が最小の形で成立し、§1 の不満（広告・サブスク・既存機能の有料化）に一切触れない。
5. にぶらしで学んだ並べ方の知見は、そのまま案3の「板」と案1の一枚絵の絵作りに効く。
