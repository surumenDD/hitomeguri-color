## 完全再現と v2 の移植

元画像をバイパスして返す処理はない。元パレット Q=P を与え、OKLab の差分合成・シェーダの色域変換・sRGB への逆変換・8bit 出力を通して、原寸の全 RGB チャンネルを比較した。透明度を持つ別の合成画像でも RGB と alpha の完全一致を確認した。

| 画像      | 原寸      | 元パレット | 台本0秒 | 台本24秒 |
| --------- | --------- | ---------- | ------- | -------- |
| flat      | 1536×1024 | ∞          | ∞       | ∞        |
| painterly | 1536×1024 | ∞          | ∞       | ∞        |
| pixel     | 1672×941  | ∞          | ∞       | ∞        |
| photo     | 1536×1024 | ∞          | ∞       | ∞        |

港と湖は、パレット・位置統計からの役割の推定・台本の出力を試作 v2 と比較した。16色の抽出は最大成分差0、役割は全件一致。全6役割を各16色へ割り当て、0〜24秒の721時点（30fps、終点込み）を調べた台本の最大成分差は0だった。

追加指定に従い、時点の状態を original / afterglow / blueHour / midnight / lateNight / twilight / sunrise / morning で引けるデータにした。「1日の光」は元の秒数/24の割合を持つ sequence。役割の遅れと包絡は v2 の式のまま、揺らぎ周期は durationSec/8 と durationSec/5。nightDepth と glow は引数にあり、1の出力を保証する。1以外の効果は未実装として明示的にエラーにし、メインが未決定の式を作っていない。

### 明度の範囲外の扱い

港の座標 (515,554)（左上が原点、0始まり）の1画素は、元の L=0.0382731371。Shepardで合成した L は7.2秒に -0.0017364974、11.4秒に -0.0075441659、14.6秒に -0.0032595182 だった。Gaussian では範囲外にならない。

メインの18:31:33 UTCの追加指示に従い、診断は丸め前の値で数え、通常の描画では L だけを [0,1] に収めてから L・色相を保つ彩度の二分探索を行う。sRGBの各チャンネルを切り捨てる方法へ置き換えていない。上下両方の範囲外を人工的に作ったブラウザテストでも、診断に出ることと通常描画の黒・白への到達を確認した。台本の数値は変えていない。根本の編集上限の検査はM2。

## 処理時間

2MP相当は港を1732×1155（2,000,460画素）に拡大した画像。Workerは毎回新規で、3回の全前処理を測った。内部時間は色変換・抽出・番号割当て・重み・位置統計をすべて含む。外側の時間はWorker起動・転送を含む。

|  回 | 全前処理 ms | Workerを呼ぶ外側の時間 ms |
| --: | ----------: | ------------------------: |
|   1 |       420.0 |                     445.5 |
|   2 |       422.1 |                     442.3 |
|   3 |       424.7 |                     435.7 |

3回とも1秒以内。配列の容量は2MPで 162,037,260 バイト（約154.5MiB）。GPU側にもテクスチャを持つため、モバイルのメモリ量と圧縮は引き続き確認が必要。

1080pの描画は12回のウォームアップ後31回。GPUタイマークエリの中央値 3.205ms、1画素のreadbackで同期した外側の中央値 3.5ms、最大 57.3ms。中央値は60fpsの16.7msの範囲内だが、この値は実機の持続フレームレートや低性能GPUの保証ではない。最初に出たreadbackなしの約0.31msは採用せず、この同期付き測定を最終値にした。

Taskは `task_e8d8b0f9e4ab`、Dispatchは `ctx_1710b0affc33`。`tools/orca/dsh-launch.sh` を Run `run_b192743c5933` で実行し、画面下のモデル名と送信を確認した。入れ子のdepth 2で起動でき、深さ制限の失敗はなかった。成果の2ファイルを読んでからテストを再実行し、受け入れ後に worker-release した。端末の終了もOrcaが確認している。
