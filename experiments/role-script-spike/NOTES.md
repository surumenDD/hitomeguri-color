# 役割ごとの色の台本

2026-10-27。読む人は、ADR-0003 の既定の時間設計と、次の分解方式を判断する設計者・実装者。

## 判断と目視

**役割ごとの台本は進める価値がある。ただし自動推定だけで作品を仕上げる段階には届いていない。** 深夜の空・水・影を落としながら窓を暖色に残すと、従来の全色共通の回転より「その場所の光」に見える。2枚の8時点一覧、従来 c との同時刻比較、同じ分解を使った比較、960px幅の深夜画像、操作画面を実際に開いて判断した。

| 見たこと | 港 | 湖 |
|---|---|---|
| カラーフィルタに見えないか | 深夜は空と山が沈み、窓・提灯・月が別の明るさで残る。従来 c の一面の青緑と桃色より改善。ただし朝の青緑と夕方の黄色は全面の色かぶりにも見える | 空の筆致、暗い木々、窓と反射に違う明るさが出る。夜は改善。夜明けは空と湖を同時に薔薇色へ染める印象がまだ強い |
| 灯りが灯りに見えるか | 窓は琥珀色で暖かく残る。提灯にも色は残るが、赤い縁や一部の窓は空の色を受ける。窓の塗り方を完全にそろえられてはいない | 小屋の窓と縦の反射が暖かい。窓の中心の一部は別の空色に混ざり、暗い格子や緑がかった細片が残る。岸の石・草にも同じ暖色が漏れる |
| 夜が夜に見えるか | 11.4秒では家と舟がシルエットになり、灯りの相対的な強さが出た。暗部はかなり落ち、石垣の細部は読みにくい | 11.4秒では夜に見える。従来 c の夜は明るい青い夕景に見えた。今回は前景の葦や岩の細部を暗くしすぎる面もある |

同一の16色・同一の固定重みでも、11.429秒の従来の規則は明るい青緑の風景と桃色の光、役割の台本は暗い風景と琥珀の灯りになる。色数を増やしただけの改善ではない。一方、比較の全長は左20秒・右24秒なので、ほかの同じ秒数の行が同じ段階に当たるとは限らない。夜の行以外も含めて、速度や時間配分の優劣をこの4枚だけで断定しない。

### 写真調の太陽は失敗例として残す

[写真の8時点](results/photo-eight-times.jpg)と[従来との比較](results/photo-comparison.jpg)を見た。日輪の位置は残るが、深夜の太陽は白〜青緑に寄る。太陽周辺と反射の大きな暖色は「空」に入り、小さな最明部だけが「灯り」になるため、柔らかい重みの混合では温かさを保てない。灯台の灯りも独立した島にはならなかった。朝の空と海は強い青緑、夕方の岩には黄緑が出る。**写真の自然な一日は、この試作では成立していない。**

仮に太陽を完全な「灯り」に固定しても、夜の水平線に暖かい太陽が浮いたままになる。窓・月・太陽をひとつの光源役にまとめる限界がある。太陽の消灯・残照と、窓の点灯を別の役割にすること、同色を空間で分けることが次の課題。形を変えない本試作は天体の移動を表現しない。

## 役割と時間の設計

Ferrari の絵とパレットの作り込み、長さ・速さをそろえない循環、Huckaby の「動かす色を選んだだけでは成立しない」という経験、Pixar の全体の連続性、Turrell の薄暮という `docs/research/synthesis.md` 3節の知見を出発点にした。ここでの数値・色・推定条件は、その知見から作った試作上の設計値であり、先行作品の再現や知覚実験の結果ではない。Purkinje 現象はモデル化しておらず、調査外の生理モデルによる正しさは主張しない。

共通の目印は **0、2.8、5.2、8.2、13.6、15、17.2、20、24秒**。区間の長さは **2.8、2.4、3.0、5.4、1.4、2.2、2.8、4.0秒**。深夜を長く取り、薄暮と夜明けの色を別に作った。キー間は OKLab の直線と `u²(3−2u)` で補間する。

| 役割 | 台本 | 空との時間差 |
|---|---|---:|
| 空 | もともと暖かい水平線を金へ、残照は薔薇、菫、彩度を落とした深い藍。夜の終わりは淡い青緑、その後に桃、朝は青緑。元のLの上下関係を残す | 0 |
| 水 | 同じ目印を追うが、空よりLを0.018〜0.036下げ、彩度を0.86倍にする。自発光に分類された反射は温かく残る | 最大0.65秒遅れ |
| 灯り | 周囲が暗くなるほどLを少し上げ、色相を72°から65°の琥珀へ。小さな光はL 0.72以上を目標とする | 最大0.45秒先行 |
| 影 | 夜は青寄りの低彩度へ。真っ黒な画素の差分を負にしないよう、最暗部を少し持ち上げる。夜明け・朝に明るさを戻す | 最大0.25秒遅れ |
| 中間 | 夜はLと彩度を下げ、青を弱く混ぜる。昼の暖色・緑をすべて同じ色相に置換しない | 最大0.38秒遅れ |

時間差には `sin²(πt/24)` の包絡を掛ける。したがって夕方の継ぎ目では差が0になり、周回時に台本の異なる時刻を接続する破綻を防ぐ。「最大0.65秒遅れ」は常時0.65秒ではない。水と空が同じ画素を共有してしまう場合は、この遅れも混ざる。

灯りの揺らぎは3秒と4.8秒の正弦波、Lの合計振幅は最大0.0018。包絡で周回の端を0にする。両周期は2秒以上で、24秒を割り切る。再生速度を変える機能は持たせていない。

### 方向づけから変えたこと

- 上空の青をすべて金にすると平らな黄緑のフィルタになるため、夕方の金は元から暖かい色を中心にした。青い空は青から始める。
- 最初の8色では小屋の窓が夕焼けの大きな暖色に吸収されるため、16色に増やした。色を0.04L・0.03a・0.03bで区切った箱の標本数の平方根の逆数で、k-means時の寄与を調整し、小面積の色が消えにくくした。32768標本・最遠点の初期化・20回以内の反復は既存の試作を踏襲する。この抽出の変更と、画素の再合成の重みは別である。
- 柔らかい重みの幅は最近隣パレット距離の中央値×0.45を0.025〜0.045に収めた。既存の幅では琥珀が空へ広く漏れたため狭めた。ただし局所性と滑らかさの最終方式はこの試作では決めない。
- 影をそのまま半分のLへ落とすと、写真の完全な黒を含む残差でLが負になった。影のキーに小さなオフセットを加え、最終の3画像×8時点では原寸全画素のL範囲外を0にした。キー間の全時刻の原寸診断まで保証する検査ではない。

表現は ADR-0004 の `y = x + Σw(Q−P)`。重みは読み込み時に一度だけ求め、その後は変えない。OKLabの差分と元画像を残し、色域外はLと色相を保って彩度を二分探索で下げる。元の階調や筆致は残るが、極端な再配色で材質や明るさの順序を保つ保証ではない。1画像の前処理配列は約120MiBで、モバイル向けのメモリ設計ではない。

## 自動推定

物体認識ではなく、各パレット色の最近傍領域を数えて推す。位置の原点は左上。`上部` は y < 0.48、`下部` は y > 0.58 の画素の割合。面積順の色番号で表示する。

判定は次の順で最初に当たるものを採る。

1. L < 0.30 → 影。
2. L > 0.73、C > 0.065、色相25〜105°、面積3.5%未満 → 灯り。ただし上部が60%以上なら除き、面積0.8%未満の極小色だけは月などの候補として残す。
3. L > 0.46、C > 0.085、色相25〜105°、面積0.6%未満、上部40%未満 → 暗めの灯り・反射の候補。
4. 上部56%超かつL > 0.39 → 空。
5. 下部52%超かつL > 0.32 → 水。
6. L > 0.60、重心y < 0.52、C > 0.045 → 空。
7. 残り → 中間。

**境界は手で選んだ仮説で、汎用性は検証していない。** 港の11番は窓、12番は主に下部の反射、15番は月を灯りとした。湖の16番は窓・反射・岸の一部をまとめて灯りとした。湖の14番の明るい夕焼けを灯りから外したことで、深夜も水平線が光り続ける最初の失敗は減った。しかし湖の15番の暖色の一部は水、港の4番の雲と反射はまとめて水になる。同色の場所を分けられないことが、手で役割を変えても残る限界である。

## 光の連続性と操作の検査

Chrome **155.0.8059.86**、Windows、headless、DPR 1。外部リクエストを撮影側でも遮断し、120レスポンスはすべてループバック。ブラウザ実行時エラー0、失敗リクエスト0。自動再生なし、役割変更とリセット、色番号の場所表示、再生と停止、時刻スライダー、画像切り替え、390px幅ではみ出しがないことを確認した。

`tools/visual-qa/flash-check.mjs` はこの実行時点では存在しなかったため、自前の [measure-video.mjs](measure-video.mjs) で**書き出したMP4を全画素・全720コマデコード**した。sRGBを線形化し、`Y = 0.2126R + 0.7152G + 0.0722B` を求める。隣接フレームの全画面平均Yの差と、各画素のY差の絶対値の平均を測る。最終→先頭も1組として含める。

| MP4 | 平均Yの隣接差 最大 | 画素ごとの絶対Y差の平均 最大 | 継ぎ目の平均Y差 | 判定 |
|---|---:|---:|---:|---|
| 港 | 0.00137832 | 0.00163050 | 0.00020926 | 連続性の確認値内 |
| 湖 | 0.00142111 | 0.00198812 | 0.00033699 | 連続性の確認値内 |

単位は0〜1の相対輝度。今回の簡単な検査では、それぞれ0.02未満・0.03未満を確認値とした。規格の合否値ではない。港の単一画素の差の最大は0.15978だが、差0.1以上になった面積の最大は1画素相当（全体の0.000163%）。湖の単一画素差の最大は0.04501。圧縮前の港499→500コマでは単一画素差0.00680、継ぎ目では港0.00329・湖0.00459で、MP4の局所差には圧縮の影響がある。CRF18から12へ上げて局所的な圧縮誤差を減らしたが、局所の無変化を保証するものではない。

この結果で確認したのは依頼にある「隣り合うコマの平均の明るさが急に変わらないこと」。実際のディスプレイのcd/m²、飽和赤の反転回数、ITU/WCAGの領域・時間窓による点滅判定は測っていない。**P7全体への適合認定ではない。** 写真は静止画8時点を見た補助試験で、動画の検査対象は港と湖の2本。

## 残る判断

まず「窓・太陽・月」「空・雲・空の反射」「窓の反射」を使い手が空間で分離できることを優先したい。役割は5種類から始められるが、光源をひとつにまとめる既定値では写真の一日を作れない。灯りの強さを含む台本を直す操作も必要で、今回は役割の付け替えだけを試した。

港の金と朝の青緑、湖の夜明けの薔薇色はまだ「色を変えた」印象が強い。これを完成した既定値とはしない。次は重みの別試作の結果を合わせ、同じ分解・同じ役割で台本だけを比較し、夕方を長く眺めても飽きない配分へ調整する。

変更はこのフォルダ内だけ。既存の recolor-spike は読み取りのみ、コミットはしていない。作業中に別ワーカーの `experiments/weights-spike/` が作業ツリーに現れたが、変更も削除もしていない。

### v1 を目で見て直した点

| v1 で見えたこと | 原因 | v2 の直し方 |
|---|---|---|
| 始まり（0秒）の空が黄土色と緑の帯になり、元の絵の夕焼けから離れた | キー0で空を金色に置き換えていた | キー0と最後のキーを元のパレットそのものにした。台本は元の絵から離れ、元の絵に戻る |
| 夜明けが一様な赤茶、朝が一様な青緑で、フィルタに見えた | 空・水・影・中間が、キーごとにほぼ同じ色相へ寄せられ、元の暖色と寒色の対比が消えた | 空と水の各色について、元の色の暖かさ（`warmth()`）を測る。暖色の側（地平・映り込み）と寒色の側（上空）に、キーごとに別の目標を与えて混ぜる。夜明けは「金の地平・青い上空・菫の影」にした |
| 朝になっても窓が灯ったまま | 灯りの台本に「消える」がなかった | 灯りは残照でともり、夜に琥珀で最も明るく、夜明けに弱まり、朝には周りになじむ |
| 月が昼も同じ色 | 月が灯りと同じ扱いだった | 役割「天体」を足した（上部に85%以上の、ごく小さく明るい色）。夜は青みのある淡い白、朝は空に溶ける |

暗くするキーでは、最も暗い画素の差分が負にならないよう、暗くするほど床を持ち上げる。明るくするキーは白へ近づける形にして、元の明るさの順序を保つ。式は `darken()` にある。

### 結果

- 目視（`results/flat-eight-times.jpg`、`results/painterly-eight-times.jpg`）: 残照の菫と桃、ブルーアワー、琥珀の灯りが残る深夜、金の地平と冷たい上空の夜明け、灯りが消えた淡い朝。どの時点もフィルタには見えない。
- 残る点: 湖の絵では、小屋の窓が暖色の「水」と判定され、朝も黄色く光る（朝日の照り返しにも読めるが、役割の付け替えで直る）。「夜の終わり（14.6秒）」はすでに地平が暖かく、夜明け前の薄明として読める。写真調の太陽は v1 と同じく失敗例のまま。
- 検査: 3枚 × 8時点で原寸の L の範囲外は 0。24秒の動画（30fps、720コマ、継ぎ目を含む）で、隣り合うコマの平均の明るさの差は最大 0.0033（flat）・0.0028（painterly）、0.1 以上変わる画素の面積は 0。ITU・WCAG の正式な判定ではない（`tools/visual-qa/flash-check.mjs` ができたら改めてかける）。
