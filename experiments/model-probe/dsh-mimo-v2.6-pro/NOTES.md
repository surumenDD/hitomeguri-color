# NOTES — Chromatic Field（dsh-mimo-v2.6-pro）

## 設計の意図
- OKLab で混ぜ合うパステルの「色の場」。派手な発光ではなく、光が滲む静かな画面を目指した。
- 色の混合・補間はすべて OKLab / OKLCH で行い、sRGB 値どうしの直接混合は使っていない（R1）。

## 描き方と選んだ理由
- WebGL2 のフラグメントシェーダで描画（R8）。理由: 1920×1080 60fps で、多数の色の塊の OKLab 混合と gamut mapping を毎フレーム Canvas2D（CPU）で行うのは重い。GPU ならピクセル単位で「OKLab 加重平均 → OKLCH → C の二分探索」がそのまま書ける。
- 各画素でガウス的な重み付き OKLab 平均を取り、得られた OKLCH の L と h を保ったまま C を二分探索（シェーダ内 18 回、JS 側 32 回）で下げ、sRGB の中へ収めてから表示する（R2）。チャンネルの切詰めは最終的な 8bit 化のときだけ。
- PNG 保存（S）は preserveDrawingBuffer を立てず、キー押下時に1フレーム描いてから同期的に toBlob で保存する（常時描画の遅さを避けるため）。
- 広い基礎 blob（半径 2.2）を1つ置き、その上にパレット5色の塊を重ねる。これで画素の重み和がゼロにならず、どこも自然に色づく。

## 調和の規則（R3、コード内コメントと同じ）
- 類似3色（h0, h0+26°, h0+52°）＋補色2色（h0+180°, h0+206°）。L は明るい側（0.78–0.86）と中間（0.52–0.62）を交互に、C は 0.055–0.13 の低彩度に抑える。h0 はランダム、Space で再生成する。

## 動きと入力
- 5つの塊の位置・半径を 38〜61 秒周期のサインで動かす（R4: 1周期 20 秒以上）。点滅や急な明るさ変化は作らない（R10）。
- ポインタ押下でパレットの色を順に選び、押した位置とドラッグ軌跡に注入する。半径は 2.8 秒で広がり、8秒保った後10秒かけてフェードして場になじむ（R5）。
- `prefers-reduced-motion: reduce` のときは自走時計を止めて動きを完全に止め、注入したときだけ半径が即時に広がる形で画面が変わる（R7）。

## 要件の対応・残り
- R1〜R10 はすべて実装した。意図的に満たしていないものはなし。
- 確かめたこと: (1) selftest の数値を Node 24 で同じ関数を実行し、`srgbToOklab` 5色が既知の基準値と小数4桁一致。(2) gamut mapping は h=150° のとき h=150.03°・L=0.7005 で、色相と L が保たれる（誤差は 8bit 化のみ）。(3) Edge ヘッドレスで index.html を実描画し、画面が黒でなく滑らかな色になっていること、30秒後のフレームとの画素差分が平均 39/765 でゆっくり変化していることを画像の画素統計で確認。(4) `?selftest` を実ブラウザで開き、DOM に JSON が出ていることを確認。
- 確かめられなかったこと: 1920×1080 でのフレーム時間（60fps の実測）。S キー保存・Space 再生成・ドラッグ注入の実際の動作（ヘッドレスでは入力を送れない）。`prefers-reduced-motion` の挙動。画面の美しさの目視（このモデルは画像を見られないため、画素統計でのみ確認）。
- 時間があれば直す点: 注入は最大16個で、古いものが消えるときのなめらかさ。Display P3 表示対応。ドラッグ速度に応じた注入量の調整。
