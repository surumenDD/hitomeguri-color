# 試走課題: Chromatic Field

実装を任せるモデルを選ぶための比較。同じ課題を各モデルに解かせ、メインが同じ基準で評価する。成果物は製品には使わない。

## 作るもの

`index.html` を1つ。外部依存なし（CDN・npm・ビルドなし）。ブラウザで開くと全画面に色の場が描かれ、ゆっくり変化し、ポインタで色を差し込める。

## 要件

- **R1** 色の計算は OKLab / OKLCH で行う。sRGB の値どうしを直接混ぜない。
- **R2** sRGB の色域から外れた OKLCH の色は、L と h を保ったまま C を下げて収める（二分探索など）。各チャンネルを 0〜1 に切るだけの処理は不可。
- **R3** 起動時に OKLCH で5色のパレットを作る。使った調和の規則を、コード内のコメントで1〜3行説明する。Space キーで作り直す。
- **R4** 画面は、パレットの色が柔らかく混ざり合う色の場にする（ぼかした色の塊、メッシュ状のグラデーションなど。描き方は自由）。何もしなくても、ゆっくり（1周期 20 秒以上）変化する。
- **R5** ポインタを押してドラッグすると、その位置にパレットの色の1つ（押すたびに順に替わる）が差し込まれる。差し込んだ色は周りの色と OKLab で混ざりながら広がり、数秒かけて場になじむ。
- **R6** S キーで、いまの画面を PNG で保存する。
- **R7** `prefers-reduced-motion: reduce` のときは、自走する変化を止め、入力したときだけ変わる。
- **R8** 1920×1080 で 60fps を目指す。WebGL2 か Canvas2D かは自由。選んだ理由を NOTES.md に書く。
- **R9** URL に `?selftest` を付けると、描画の代わりに次の結果を JSON で `<pre>` に表示し、`console.log` にも出す。
  - `srgbToOklab`: `#ff0000` `#00ff00` `#0000ff` `#ffffff` `#808080` の L, a, b（小数4桁）
  - `oklchToSrgbMapped`: `oklch(0.7 0.4 150)` と `oklch(0.5 0.05 30)` を R2 の方法で sRGB に収めた結果（16進）と、そのときの C
- **R10** 点滅させない。全画面の明るさが1秒に3回以上大きく変わる変化を作らない。

## NOTES.md（40行まで）

設計の意図、描き方を選んだ理由、調和の規則、R1〜R10 のうち満たせなかったものとその理由、時間があれば何を直すか。

## 評価（メインが行う）

- 正しさ: `?selftest` の値が基準値と小数3桁で合うか。色域に収めるとき色相が保たれるか。
- 要件: R1〜R10 をいくつ満たすか。
- 見た目: 起動直後・数十秒後・ドラッグ後の画面。色の美しさ、品のよさ、ありがちでないか。
- コード: 読みやすさ、構造、余計なものがないか。
- 速さ: 描画のフレーム時間。
