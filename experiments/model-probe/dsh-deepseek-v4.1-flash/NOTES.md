# Chromatic Field — NOTES

## 描き方（R8）
Canvas2D では 5 色の混色をピクセル単位でできず、ImageData で CPU 計算すると 1920×1080 は 60fps に届かない。1 パスの GPU 計算で済む WebGL2（フルスクリーン三角形 + フラグメントシェーダ）を選んだ。フレーム時間が 21ms を超えたら描画解像度を 0.86 倍に落とし、余裕があると戻す。

## 色（R1, R2）
- パレットは CPU で OKLab にし、シェーダは OKLab のまま加重平均 → 最後に 1 回だけ sRGB へ。途中で sRGB を混ぜていない。
- 色域外は L と h を固定し、C を二分探索で下げる（JS 24 回 / シェーダ 9 回）。チャンネルのクリップは使っていない。

## パレット（R3）
- split-complementary: 基準色相 h0 の ±26° と h0+180°±26° の 5 色。明度は 0.30〜0.86 に散らし、明るい面と沈む面を作る。
- Space で作り直す。切替は 1.1 秒かけて OKLab で補間する。

## 場（R4）
- 5 つのブロブ中心を Lissajous で移動（周期 37/43/53 秒）。fbm のドメインワープ（0.018 rad/s）で境界を崩し、1/(d^2.5+0.02) の重みで混ぜる。
- 自走は最短でも 37 秒周期。点滅する要素はない（R10）。

## ポインタ（R5）と保存（R6）
- 押すたびにパレットの次の色。ドラッグ中は 160ms / 画面 4.5% 間隔で注入。
- 注入は OKLab で mix。半径 0.05→0.13 に広がり、6 秒かけて消えて場になじむ。
- S キーで canvas.toBlob → PNG をダウンロード。

## 動きの抑制（R7）
prefers-reduced-motion: reduce では自走時間を止め、変化があるときだけ描き直す。注入の広がりだけは入力への応答として残した。

## 検証したこと
- ?selftest の JSON が Python の独立実装と小数 4 桁で一致（#ff0000 L=0.6280 a=0.2249 b=0.1258、oklch(0.7 0.4 150) → #00be58 C=0.1928）。
- ヘッドレス Chrome（CDP・実 GPU: ANGLE D3D11 / RTX 5070 Ti）で 1920×1080、フレーム中央値 16.7ms（59.9fps）。
- 画素統計: 彩度の中央値 0.06〜0.08、ほぼ平坦な領域は 5% 未満、ドラッグの変化は中央の帯に集中。
- reduce 指定では 3 秒間の画素が完全一致。S キーの PNG blob とダウンロード link を確認。

## 満たせなかったこと・限界
- R1〜R10 はすべて実装したが、R8 の 60fps はこのマシンの実測値で、他の GPU では未確認。
- このモデルは画像を読めないため、見た目の目視評価ができていない。美しさの判断は数値と設計に基づく推測。
- 実機のブラウザで人が見た評価は未実施（ヘッドレスと CDP のみ）。

## 時間があれば
- パレットの明度配分をケースごとに調整する。注入をドラッグ方向に伸びる非等方な形にする。
